# Token Ledger Rebuild Plan

This is a planning-only specification to rebuild Token Ledger against all 76 features in `AI_Usage_Dashboard_76_Features.md`; implementation is out of scope for this session.
The current tool is a Python CLI that reads Claude Code and oh-my-pi JSONL and generates a self-contained HTML dashboard (`README.md:5-8,71-82`).
The collector already sees request-level IDs, provider fields, and token TTL fields, but its aggregate dashboard payload loses request identity/provider detail and combines cache-write TTLs; old flat cache-write records are currently assigned to the 5-minute tier (`tokentrack.py:419-487,522-540,614-661`; `README.md:97-102,183-214`).
The current project documents aggregate-only archive restoration and an 8 MiB session-detail cap; no live logs or private artifact data were inspected (`HANDOFF.md:13-29,53-65`).

## Proposed architecture (not existing capability)

Keep Python ingestion. Use SQLite as the local canonical request/event store, with versioned migrations, source coverage, provenance, and materialized rollups. Add a loopback-only query/API service and a modular local web dashboard. Recommend React/TypeScript and ECharts, built into local bundled assets, because ten pages and 76 interactive features need a maintainable UI; this is a technology recommendation, not a discovered repository capability. The web UI must make no CDN, cloud, or telemetry requests. Keep the self-contained offline HTML snapshot as an export, not the primary live interface. Local-primary distribution is recommended; retain the existing private Claude artifact only as a separately authorized publishing target. A static snapshot cannot provide live collection or write state.

Keep the six requested display identities exactly: **Opus 5.5, Sonnet 5.5, Haiku 5.5, Sol 6.1, Luna Max, and Gemini 3.8 Flash**. Configure explicit provider/model-ID mappings. Preserve original IDs and route identities. Do not infer a provider price, exact source hook, or public rate from a display name. Unknown model IDs and prices remain explicitly unknown.

Use the ten spec navigation pages without adding a new feature page: Overview; Models; Tokens & Cache; Speed; Providers & Limits; Projects; Sessions; Harness Comparison; Efficiency; Reports & Settings. Every page uses one query/filter/metric contract. “Combined” means distinct known canonical requests; if cross-source overlap cannot be resolved, show an unresolved/partial combined result rather than silently summing it.

## Reuse and cutover boundaries

- Reuse the Python JSONL parsing, cache, timezone, pricing-provenance, and harness instrumentation concepts as input adapters and baseline behavior. Do not keep two competing aggregation authorities. Today raw CLI output retains request rows, keys, provider and cache TTL fields, while dashboard/session rollups discard provider/request identity and collapse cache writes (`tokentrack.py:490-568,614-661,702-766,1150-1173`; `HANDOFF.md:27-29`).
- Preserve request observations separately from canonical requests. A provider request ID is stable only within a provider and non-secret local account alias. Multiple observations may map to one canonical request. Do not merge on matching prompt content, timestamps, model, or token counts. Keep retry attempts with distinct IDs distinct. Keep origin harness separate from the source that observed a record.
- The current OMP parser derives generation seconds as `(duration - ttft)` from millisecond fields but does not retain the original duration or TTFT; Claude Code timing is a preceding-to-last-log-line span proxy (`tokentrack.py:419-487,522-540`). Retain raw timing observations and units. Do not label a log-span proxy as measured streaming latency.
- The current parser has tool IDs/names and parent links, but dashboard output mainly retains counts and opaque session links, not a full trace; arguments and results are not exposed (`tokentrack.py:419-487,614-661,702-748`). Preserve useful event relationships, not sensitive tool payloads by default.
- The external `~/.claude/skills/token-ledger-update/merge_data.py` workflow restores old aggregate rows into a saved artifact; the handoff says the live artifact includes rows absent from current logs (`HANDOFF.md:7-11,20-23,53-65`). Preserve the saved artifact read-only. Import only supported archived aggregate partitions through a controlled local migration; do not expose or publish its embedded private `DATA`. Retain old stored cost, timezone, archive status, and grain as provenance; never manufacture request detail or subtract incompatible totals. After verified cutover, stop the external splice-and-restore path from being the canonical update path. Protect its current workflow during migration, then remove obsolete audit-slot/injection compatibility code instead of keeping permanent shims. Preserve existing local saved views and review data where it can be migrated safely; do not extend review-store scope.
- Existing private artifact rules (including the 16 MB artifact limit, single data-injection slot, and Audit markers) apply only while that old workflow remains selected. New local dashboard runtime and offline snapshot export are separate targets. Keep snapshot limits and redaction rules explicit; do not publish during implementation without separate authorization (`HANDOFF.md:31-41`).

### Fixed semantic rules

1. **Missing, zero, partial, and mixed samples:** `0` means a measured zero. Null/unavailable is not zero. Mark partial counters, unknown fields, mixed pricing status, incomplete files, and sample eligibility. Every aggregate carries measurement basis, confidence/provenance, coverage, and eligible/observed denominator. Do not compare a full sample with a timed-only or archive-only sample without labeling it.
2. **Token totals:** Provider-specific semantics state whether input includes cache reads/writes. The disjoint normalized billable counters are the basis for totals and price calculations. Reasoning tokens remain a subset of output unless a provider documents a disjoint counter. Keep reported total separately; never add it to its subsets or blindly sum overlapping provider fields. Keep unknown cache-write TTL unknown.
3. **Dedupe and overlap:** Scope stable request IDs by provider and account alias. Link repeated log observations to one request; never infer identity from equal content or timestamps. Preserve origin harness separately from observation source. Source-local IDs do not prove cross-harness identity. If a candidate overlap lacks stable identity, show an unresolved-overlap warning and incomplete/ranged combined totals, not a silently summed exact total. A retry with a new request ID is a new request.
4. **Archives:** Import only aggregate grain supported by the archived artifact. Use mutually exclusive partitions or a verified same-grain reconciliation. Replace an archive partition with complete live coverage only when keys and coverage prove the replacement. Do not subtract incompatible dates, timezones, token semantics, or grains. Keep old detail unavailable. Never count live and archived observations twice.
5. **Cost and cache economics:** Distinguish actual billed API spend, API-equivalent subscription usage, subscription fees, cache savings, and unpriced value. Use effective-date pricing and historical FX provenance. Unknown rates never become zero. Cache break-even compares the write premium against later read discounts under the applicable TTL and pricing policy; do not claim savings attribution unsupported by evidence.
6. **Speed and latency:** For eligible requests, generation TPS is output tokens divided by measured generation time, excluding TTFT when measured. Report weighted throughput (`sum(output)/sum(generation seconds)`) separately from mean/median per-request TPS. Show timed-request counts and eligibility denominators. TTFT, p90/p95, queue/start, generation, and total duration require their own measured samples; otherwise show unavailable. Label proxies and never pool them with measured streaming timing without an explicit distinction.
7. **Context and activity:** Context occupancy is not cumulative input tokens. Derive occupancy only from a supported window/measurement; otherwise show an input-volume proxy separately. Active time is the union of observed active intervals; elapsed span is first-to-last event. Any active-session heuristic is labeled. Use timezone-aware equivalent-period comparisons and correct DST boundaries.
8. **Evidence and comparisons:** Show linked evidence for insights. Waste categories may overlap, so assign each observed token to one exclusive category for totals and present overlapping signals separately. Label observed overhead separately from hypothetical avoidable volume. No model/harness effectiveness or causal claim without matched workloads, recorded outcomes, adequate samples, and visible caveats. Forecasts include uncertainty, backtests, and abstain on sparse data.
9. **Privacy:** Loopback/local by default. Redact before persistence and export. Transcript capture, content hashing/repetition analysis, Git linkage, and project inclusion are opt-in. Hashing can leak equality and enable dictionary attacks; disclose that risk. Retention/deletion must cascade to requests, events, rollups, insights, exports, and locally stored snapshots. Do not send cloud requests by default.

Ingest by file generation plus byte/line checkpoint; re-read an incomplete trailing line; detect truncation/rotation and start a new generation. Incrementally upsert observations and affected rollup partitions in one transaction. Keep expensive trace/content work behind user opt-in. Validate `Host` against the bound loopback origin and require a same-origin `Origin` on state-changing requests; reject mismatches and send no permissive CORS headers. Use local session/CSRF protection for writes as appropriate. Escape source-controlled values as text in the UI and make HTML/other exports XSS-safe.
